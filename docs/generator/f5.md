# F5 Generator

The F5 generator emits a weighted mix of syslog-shaped log lines across the F5 product portfolio. It is a single generator (`generator/f5`) with one subpackage per product, mirroring the FIX generator: adding a product later is a matter of a new subpackage that self-registers into the catalog.

All products are enabled by default. Restrict the set with `enabledProducts`, and shift the mix with `weights` (each weight must name an enabled product and be positive and finite, and so must their sum). Output is deterministic from `seed`: the same seed, product set, and start time give the same stream (negative randomizes each run). Lines carry the emission time, so the start time is part of the output.

Every worker speaks for one simulated unit. The unit's management IP and daemon PIDs (tmm, mcpd, apmd, and so on) stay fixed across lines, and each record's severity comes from its line's syslog PRI.

## Products

| Token | Product | Shape |
|-------|---------|-------|
| `asm` | BIG-IP ASM (Application Security Manager) | Remote-logging security event, `ASM:key="value",...` |
| `afm` | BIG-IP AFM (Advanced Firewall Manager) | Network firewall event, default storage format (quoted CSV) |
| `apm` | BIG-IP APM (Access Policy Manager) | Access-session lifecycle, one session ID from creation to deletion |
| `dns` | BIG-IP DNS (formerly GTM) | DNS logging-profile query and response pairs |
| `audit` | BIG-IP audit | `mcpd` 01070417 transactions, `tmsh` 01420002 commands, `pam_audit` logins |
| `nginx-plus` | NGINX-on-F5 (NGINX Plus) | `upstream_time` access log and error log over syslog |
| `nginx-app-protect` | NGINX App Protect (WAF) | Default-format security event, `ASM:key="value",...` with `json_log` |
| `irules` | iRules logging | Operator log line (`Rule /Common/<rule> <EVENT>:`) and TCL runtime errors |
| `f5os` | F5OS platform | `audit-service` session records |

## Hosts

Each product logs from the machine it runs on, and its lines and `host.name`
name that machine:

| Products | Host | With the simulated environment | Without one |
|----------|------|-------------------------------|-------------|
| `asm`, `afm`, `apm`, `dns`, `audit`, `irules` | the BIG-IP unit | the environment's F5 device (`f5-lb-01`), with its management IP | `bigip1` |
| `nginx-plus`, `nginx-app-protect` | an NGINX Plus server | a server host from the environment | the running host |
| `f5os` | the F5OS platform | `appliance-1` | `appliance-1` |

The environment always holds an F5 device when an `f5` generator is
configured. An explicit `hostname` renames the BIG-IP unit only. See
[Environment](../environment.md#appliance-generators).

Where a BIG-IP writes its fully qualified name (the DNS query log body, the
AFM header and `bigip_hostname`), lines carry the device's FQDN
(`f5-lb-01.blitz.local`). An explicit `hostname` has no domain, so it is used
there as is.

Every line is a complete syslog message, with the device's own `<PRI>` and
header. Through the syslog output it is sent as written, not wrapped in a
second header (see [Syslog output](../output/syslog.md)).

## Field fidelity and sources

F5 logging is operator-configurable: administrators choose field sets and order (logging profiles, NGINX `log_format`, iRules `log` statements). So each product targets F5's default or documented format, checked against real lines copied from F5 docs, F5 repositories, or vendor parser fixtures. Each product's tests render those real lines' own values and expect the line back byte for byte (the `testdata/` golden files and their package docs name each source).

| Product | Checked against |
|---------|-----------------|
| `asm` | F5Networks/f5-telemetry-streaming test fixtures (real remote-logging line) |
| `nginx-app-protect` | f5devcentral/NGINX-Gateway-Fabric-Lab `labs/11.waf` (two real default-format lines, `json_log` and `violation_details` included); [security-log reference](https://docs.nginx.com/waf/logging/security-logs/) |
| `afm` | [AFM default storage format](https://techdocs.f5.com/kb/en-us/products/big-ip-afm/manuals/product/big-ip-network-firewall-policies-and-implementations-14-1-0/20.html); f5devcentral/f5-big-iq-lab AFM playback events; [bug 439094](https://cdn.f5.com/product/bugtracker/ID439094.html) |
| `apm` | Real APM session lines on DevCentral; Splunk Connect for Syslog F5 fixtures; K7342 (APM logs under local1) |
| `dns` | [F5 DNS lab results](https://clouddocs.f5.com/training/community/dns/html/class2/module7/lab3.html) (real query/response lines); K65762138 |
| `audit` | F5Networks/f5-ansible issues #438 and #1677 (real device syslog); Splunk Connect for Syslog F5 fixtures |
| `nginx-plus` | [NGINX logging guide](https://docs.nginx.com/nginx/admin-guide/monitoring/logging/) (`upstream_time` format); [nginx.org syslog](https://nginx.org/en/docs/syslog.html) (local7, info); Elastic nginx integration error fixture |
| `irules` | [iRules `log` command](https://clouddocs.f5.com/api/irules/log.html); Splunk Connect for Syslog F5 fixtures (TCL error) |
| `f5os` | [rSeries security guide](https://clouddocs.f5.com/training/community/rseries-training/html/rseries_security.html) (real `audit.log` lines); K000135458 (authpriv) |

## Configuration

YAML (standalone CLI):

```yaml
generator:
  type: f5
  f5:
    workers: 2
    rate: 500ms
    hostname: bigip-prod-01     # syslog-header device hostname
    enabledProducts:            # omit / leave empty for all 9
      - asm
      - afm
    weights:                    # omit for an equal mix; each must be > 0 and finite
      asm: 5
      afm: 2
    seed: 42                    # >=0 deterministic, <0 randomize
```

Every key except `weights` can also be set by flag or environment variable:

| YAML Path | Flag Name | Environment Variable | Default | Description |
|-----------|-----------|---------------------|---------|-------------|
| `generator.type` | `--generator-type` | `BLITZ_GENERATOR_TYPE` | `nop` | Set to `f5` to use this generator. |
| `generator.f5.workers` | `--generator-f5-workers` | `BLITZ_GENERATOR_F5_WORKERS` | `1` | Number of F5 generator workers (must be ≥ 1) |
| `generator.f5.rate` | `--generator-f5-rate` | `BLITZ_GENERATOR_F5_RATE` | `1s` | Per-worker generation interval |
| `generator.f5.hostname` | `--generator-f5-hostname` | `BLITZ_GENERATOR_F5_HOSTNAME` | empty | BIG-IP unit hostname. An explicit value always wins; empty uses the environment's F5 device, or `bigip1` when no environment is configured |
| `generator.f5.seed` | `--generator-f5-seed` | `BLITZ_GENERATOR_F5_SEED` | `-1` | RNG seed: negative randomizes each run, 0 or more is deterministic |
| `generator.f5.enabledProducts` | `--generator-f5-enabledproducts` | `BLITZ_GENERATOR_F5_ENABLEDPRODUCTS` | all | Comma-separated product subset |

`weights` is a map, which has no flag or environment form, so it is YAML-only.

Programmatic (`f5.Config` in Go):

```go
type Config struct {
    Workers         int                // parallel emission workers
    Rate            time.Duration      // 1 line per Rate per worker
    Hostname        string             // syslog-header device hostname
    EnabledProducts []string           // empty = all 9 products; no repeats
    Weights         map[string]float64 // per-product mix ratio (> 0); absent = 1
    Seed            int64              // >=0 deterministic, <0 randomize
}
```

## Example Configuration

### All products, equal mix

```yaml
generator:
  type: f5
  f5:
    workers: 2
    rate: 500ms
    hostname: bigip-prod-01
```

### WAF-focused subset with a weighted mix

```yaml
generator:
  type: f5
  f5:
    enabledProducts: [asm, nginx-app-protect, afm]
    weights:
      asm: 5
      nginx-app-protect: 3
      afm: 1
    seed: 42
```
